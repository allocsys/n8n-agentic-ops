# One-click n8n host

A "Deploy to Render" button that spins up your own n8n instance -- no
server, no Docker CLI, no manual install -- so you have somewhere to import
`workflow.json` (or `mock/workflow.mock.json`) and start clicking n8n's
native "Connect" OAuth buttons for Gmail/Drive/Sheets.

This is the Phase 1 host piece of the plug-and-play plan (see the project's
Notion plan). It gets you a running n8n. It does **not** import the
workflow or connect any credentials for you -- that's Phase 2 (`SETUP.md`,
not yet written).

## Deploy

[![Deploy to Render](https://render.com/images/deploy-to-render-button.svg)](https://render.com/deploy?repo=https://github.com/allocsys/n8n-agentic-ops)

Clicking this:
- Pulls the official `n8nio/n8n` Docker image (no build step, nothing to
  maintain) per the repo-root `render.yaml`.
- Generates a random `N8N_ENCRYPTION_KEY` and a random basic-auth password
  for you -- Render does this automatically for any `generateValue: true`
  field, so no secrets live in the repo.
- Provisions a 1GB persistent disk mounted at `/home/node/.n8n`, so your
  workflows/credentials survive restarts and redeploys. (Render's free
  instance type doesn't support disks -- pick at least the Starter plan
  when the button prompts you, or workflows will disappear on every
  restart.)

## One remaining manual step

Render has no way to know a service's own public URL *before* it's
deployed, so `render.yaml` ships with three placeholder env vars
(`N8N_HOST`, `N8N_EDITOR_BASE_URL`, `WEBHOOK_URL`). After the first deploy
finishes:

1. Copy the `https://your-service.onrender.com` URL Render gives you.
2. In the Render dashboard -> your service -> Environment, replace the three
   `REPLACE_WITH_...` placeholders: `N8N_HOST` gets just the hostname
   (`your-service.onrender.com`), `N8N_EDITOR_BASE_URL` and `WEBHOOK_URL`
   get the full URL (`https://your-service.onrender.com`).
3. Save -- Render redeploys automatically with the real values, and OAuth
   redirect URIs (Gmail/Drive/Sheets "Connect" buttons in Phase 2) will
   resolve correctly.

This mirrors the one paste-in-a-URL step already documented in
`crm-worker/README.md` for `CRM_WORKER_BASE_URL` -- same reason (a
deploy-time value can't be known before the deploy exists), same fix.

## Logging in

Basic-auth username is `admin`; the password was randomly generated by
Render -- find it in the dashboard under your service's Environment tab
(`N8N_BASIC_AUTH_PASSWORD`). Change it there any time.

## After you're in

1. Settings -> Import from File -> upload `workflow.json` (or
   `mock/workflow.mock.json` if you want to try it with zero credentials
   first -- see `mock/README.md`).
2. Use n8n's native "Sign in with Google" buttons on the Gmail, Drive, and
   Sheets credential screens -- no pasting API keys.
3. For Telegram/WhatsApp/LINE (not OAuth platforms -- see the main
   README's fallback-chain note), you'll still paste a bot token /
   business API credential by hand.
4. Deploy the CRM Worker (`crm-worker/README.md`) if you haven't, and paste
   its URL into the `CRM_WORKER_BASE_URL` variable here (Settings ->
   Variables).

## Alternatives

- **Railway**: Railway's one-click templates are published through their
  dashboard/template gallery rather than a file in the repo, so there's
  no equivalent button here yet -- publishing an official Railway template
  for this repo is a manual follow-up, not something `render.yaml`
  covers.
- **n8n Cloud**: n8n's own hosted offering is the least-setup option if
  you don't mind paying n8n directly instead of self-hosting; there's no
  infra to deploy at all, just import `workflow.json` after signing up.
- **Self-hosted / Docker Compose**: still fully supported -- see n8n's own
  docs if you'd rather run it on your own server.
